# 출시 뒤 계획

## 1. 해외판 (미국, 일본) — 한국 출시 뒤 업데이트로 추가

결정(2026-11-23): 첫 출시는 한국어판으로 한국에 내고, 영어·일본어판은 다음 업데이트로 넣는다. 태어난 곳은 미국·일본 주요 도시 목록을 추가해 도시별 시간대와 경도로 계산한다.

할 일
- 풀이 문구 약 2,000개를 언어별로 다시 쓴다. 지금은 한국어 조사에 맞춰 문장을 조립하므로 문자열 치환으로는 안 된다. 문장 조립 함수를 언어별로 나눈다.
- `src/engine.js`: 한국 표준시 고정을 풀고 도시별 IANA 시간대(서머타임 포함)와 경도로 시주를 계산한다. 미국·일본 주요 도시 목록 추가.
- 화면 글자, 결제 창, 안내, 약관·개인정보처리방침의 영어·일본어판.
- 스토어 등록정보 en-US, ja-JP와 스크린샷.
- 플레이 콘솔: 출시 국가에 미국·일본 추가, 국가별 가격 확인.
- 미국·일본의 소비자·개인정보 관련 요건 확인(법률 검토 필요).

## 2. 애플 앱스토어

아직 iOS 프로젝트가 없다. 맥에서 해야 하는 작업이다.

할 일
- `npm i @capacitor/ios && npx cap add ios` (Xcode, CocoaPods 필요).
- `Info.plist`에 카메라·사진 사용 설명 추가: 관상의 "지금 찍기"와 "사진 고르기"에 필요하다. 없으면 앱이 종료된다.
- RevenueCat iOS 공개 키를 `src/pay.js`의 `iosKey`에 넣고, App Store Connect에 소모성 인앱 상품 `reading_1000` 등록.
- iOS에서는 "열람 코드" 버튼을 숨긴다. 애플 심사자는 샌드박스 결제로 유료 기능을 볼 수 있고, 코드로 유료 콘텐츠를 여는 기능은 인앱결제 지침에 걸릴 수 있다.
- 아이콘, 스플래시, 스크린샷(6.7인치 등 애플 규격).

위험
- 운세 앱은 심사 지침 4.3(b)의 포화 카테고리로 반려 가능성이 크다. 싹싹 클린과 같은 개발자 계정이므로 반복 제출은 피한다.
- 사주와 관상을 겹쳐 읽는 점, 기기 안에서만 처리하는 관상 측정을 차별점으로 심사 메모에 적는다.

## 영어판 (1.6에서 완료)

구조: `src/i18n.js`가 언어(`LANG`)를 정하고 `T(한국어, 영어)`로 문장을 고른다. 기기 언어가 한국어면 한국어, 그 밖에는 영어로 뜨고, 화면 맨 아래 단추로 바꾼다. 표의 열쇠(비견, 목 등)는 한국어 그대로 두고 화면에 보일 때만 영어 이름표를 쓴다.

- 영어 문장과 표: `src/en-data.js`(사주·타로·용어), `src/en-saju.js`(분야별·자리별 풀이), `src/en-match.js`(궁합), `src/en-face.js`(관상). 한국어 문장을 고치면 같은 자리의 영어도 고친다
- 해외 출생: 영어 화면은 열두 시 대신 태어난 곳(주요 도시 약 75곳)과 시계 시각을 받는다. 그 도시의 시간대(서머타임 포함)로 세계시를 구하고 경도로 태양시를 구해 시주를 세운다(`engine.js`의 `WORLD`, `withPlace`). 한국어 화면의 계산은 그대로다
- 확인한 것: 영어 모드에서 다섯 탭과 결제·안내 창에 한글이 남지 않음(어린이, 고령, 시 모름, 음력, 친구 궁합 포함). 서울을 고른 영어 입력과 한국어 입력의 명식이 같음. 입춘 전후로 년주·월주가 바뀜
- 남은 것: 약관·개인정보처리방침 영어 페이지 공개(초안은 `docs/privacy-policy-en.md`, `docs/terms-en.md`), 영어 원어민 검수, 일본어판, AI 상담용 명식 요약의 영어화(앱에서는 쓰지 않는 기능)
